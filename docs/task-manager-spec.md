# タスク管理ツール 仕様書

作成日: 2026-10-20
用途: 別チャットでの実装用の引き継ぎ資料

---

## 1. 目的

「あれもやりたいが、これもやらねばならず、何から手を付けるか分からない」状態を回避する。
**判断そのものをAIに委譲し、自分は実行だけに集中する**ための道具。

位置づけは単なるタスク管理ではなく「脳の拡張」。思いついたことを片端から投げ込めば、
AIが整理・分類・接続・スケジューリングまで引き受ける。

### 核となる挙動（最重要）

バラバラに投げ込まれた断片を、AIが結合して実行可能なタスクとして立ち上げる。

```
「ワールドを作りたい」            → 願望（締切なし・素材）
「HDAがたまたまできた」            → アイデア/日記（締切なし・素材）
「再来週に交流会イベントがある」    → 予定（日付あり・接続の起点）
          ↓
AI: 「では再来週までにHDAでワールドを作りませんか？」
```

照合のトリガーは **日付のあるものが投入されたとき**。
その予定に差し込める素材が手持ちにあるかをAIが照合し、提案する。

## 2. 画面構成

### デスクトップ
| 領域 | 比率 | 内容 |
|---|---|---|
| カレンダー | 1/2 | 月／週表示。優先度を色分け |
| タスクリスト | 1/4 | 項目の羅列 |
| チャット欄 | 1/4 | 投げ込み口 ＋ 個別対話 |

### モバイル
タブで切り替え。

### 横道の吹き出し
チャット欄の内部、またはその脇にオーバーレイで、AIからの脇道提案を表示する。
本流の対話を止めずに視界の端に置くことが目的。独立した枠は設けない。

## 3. データ構造

### 3.1 項目の種別（タグで保持）

| 種別 | 締切 | 役割 |
|---|---|---|
| 願望 | なし | 素材。「いつかやりたい」 |
| アイデア／日記 | なし | 素材。「できた」「気づいた」 |
| 予定 | あり | **接続の起点**。これの投入が照合を起動する |
| タスク | 任意 | 実行可能な単位 |

### 3.2 フォルダとタグ（二軸）

- **フォルダ** = 領域（就活／サークル／制作／学習／生活）
- **タグ** = 種別およびその他の属性

いずれもAIが自動推定して付与する。
タグは自動生成するが、**既存タグを優先して再利用**し、乱立を防ぐ。
定期的にリファクタリングを行い、近接するタグは統合する。

### 3.3 状態（3段階）

`未着手` / `進行中` / `完了`

### 3.4 階層（2階層）

親タスク配下に子タスクを持つ。
**親の状態は子から自動算出**する。

- 子が1つでも進行中 → 親も進行中
- 子がすべて完了 → 親も完了

### 3.5 日付

- 開始日＋締切日（期間を持てる）
- 繰り返し（毎日／毎週など）に対応し、習慣枠を扱う

### 3.6 入力項目

ユーザーが入力するのは **カテゴリ・締切・状態の3つのみ**。
所要時間、集中度、場所などの属性は持たせない（必要になった時点で追加する）。

---

## 4. 入力

### 4.1 投げ込み口は1つ

思いついた順に、形式を問わず投げ込める単一の入力欄。
願望・アイデア・予定・タスクの区別はユーザーが行わず、**AIが切り分ける**。

### 4.2 チャット欄の性質

- **基本** — 入力専用。投げ捨て式のメモとして扱い、応答は最小限
- **個別** — タスクや予定を選択したときのみ、そのアイテムについて対話できる

### 4.3 音声入力

将来的に対応。既存の「音声入力→MCPでソフトを動かす仕組み」と接続する前提。

---

## 5. AIの振る舞い

### 5.1 分類

投げ込まれたものを種別・フォルダ・タグに自動で振り分ける。

### 5.2 接続と合体

素材どうし、または素材と予定を結合し、実行可能なタスクとして提案する（§1参照）。

### 5.3 スケジューリング

心理学的な根拠に基づいて配置を判断する。

- 習慣として定着させたほうがよいものは、繰り返し枠として時間を指定して入れる
- 実装意図（implementation intention）の形——いつ・どこで・何を——を満たすように配置する

### 5.4 再配置

**ユーザーが依頼したときのみ実行**する（自動では走らせない）。

未消化のタスクを締切から逆算して空き枠に振り直す。
詰まりすぎている場合は「これは落とす」判断も含める。
落としたものは**保留に戻し**、棚卸しのときに再浮上させる（削除しない）。

### 5.5 再浮上（B＋C の複合）

- **定期的な棚卸し** — 眠っている項目をまとめて提示し、やる／寝かせる／保留を判断する場を作る
- **文脈に応じた自動浮上** — 関連する作業をしているときに、該当する素材を提示する

### 5.6 外部からの持ち込み

ツール内の項目を再提示するだけでなく、**外部の情報を取得して既存のタスクに接続する**。

例: 知らないHoudiniの機能を調べて「これが使えそう」と提案する。

Web検索を伴うため、ツール単体では完結しない。Claude側が調べて提案し、ツールはそれを受け取って保持する。

### 5.7 提案のタイミング

**対話中に随時**差し込む。加えて、画面端の吹き出しにピックアップして表示する（§2参照）。

### 5.8 締切の提案

締切は基本的にユーザーが設定するが、**AIからも提案する**。

## 6. カレンダー連携

### 6.1 方式

Google Calendar API でツールから直接書き込む。
Galaxyの純正カレンダーウィジェットがそのまま表示に使えるため、ウィジェットの自作は不要。

ICSフィード購読方式は取得間隔が長く（数時間〜1日）、習慣枠の頻繁な入れ替えに追従できないため採用しない。

### 6.2 書き込み範囲

**すべて書き込む。**

- 日付が確定しているもの（面接、応募期限、イベント）
- 習慣枠（デッサン、Duolingo、語学など）
- 日々の作業タスク

混雑は許容する方針。不便が出た時点で調整する。

### 6.3 専用カレンダー

書き込み先として専用カレンダーを1本作成し、既存の予定と分離する。
まとめて表示／非表示を切り替えられるようにする。

### 6.4 色分け（優先度）

Googleカレンダーは予定ごとに11色から選択可能。暫定案:

| 色 | 対象 |
|---|---|
| 赤 | 締切が迫る／落とせないもの（面接、応募期限） |
| 橙 | 依存の起点になるもの（企業連絡、大学交渉） |
| 青 | 通常の作業タスク |
| 緑 | 習慣枠 |
| 灰 | 任意・余裕があれば（積読、積みゲー） |

### 6.5 オフ日

「オフ」という予定として明示的に入れられるようにする（詳細は運用しながら詰める）。

## 7. 技術前提

- PCとスマホのブラウザから利用する
- データは外部から取得できる場所に保持する（ブラウザ内のみに閉じない）
- Androidのホーム画面ウィジェットはネイティブアプリ（APK）でなければ作れないため、純正カレンダーへの書き込みで代替する

## 8. 締切のないタスクの扱い

締切のないもの（デッサン、Maya習得、Linux、積読、積みゲーなど）には、
**締切を付けない。** タイムブロッキングや仮の期日も設定しない。

フォルダの上階層にそのまま置き、**接続待ちの素材として寝かせる。**
後から日付を持つ情報が投入された時点で掘り出され、実行可能なタスクとして立ち上がる。
§1の核となる挙動が、締切なしタスクにもそのまま適用される。

### 例

```
やりたいこと
  デッサン                                          ← 締切なし。放置でよい
    「石膏像の貸し出しが冬休みに申請可能」          ← 日記として投入
                    ↓
AI: 「冬休みに入ったら、まず申請をしませんか？」    ← 冬休みという日付に接続して掘り出す
```

## 9. 開発方針

アジャイル的に進める。作りながら調整するため、以下は事前に決めない。

- 吹き出し表示の具体的なレイアウト
- リファクタリングの実行間隔（定期的に実行させる運用で対応）
- GUIの細部
